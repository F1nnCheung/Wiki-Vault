# Prompt 工程三板斧

Prompt 工程三件套：Few-shot（格式稳定）、Chain-of-Thought（推理准确）、Self-Consistency（答案稳定）。三者组合使用，推理准确率可提升 35-50%。

## 一、Few-shot：示例的力量

### 核心原理

Zero-shot 不给任何例子；Few-shot 在 Prompt 中放几个「输入→输出」示例，让模型学会你想要的**格式和推理模式**。

**关键数据**：同一个情感分析任务，零样本格式稳定性约 60%，三样本后直接到 95%+。

> 示例不是「举个例子」，是在给模型校准输出模式。

### 静态 vs 动态 Few-shot

- **静态 Few-shot**：示例库小（< 20 条）时用，固定几个示例
- **动态 Few-shot**：示例库大时，按输入相似度自动选最相关的 k 个示例，控制 token 预算

### 核心坑

示例质量差，比不给示例更糟。示例里有错误、格式不一致，或示例和测试数据分布差异太大，会主动干扰模型输出。

---

## 二、Chain-of-Thought（CoT）：思维链

### 核心原理

LLM 的前向传播是一次性的，中间状态不能回头修改。**强迫它把推理步骤写出来，相当于给每一步推理都分配了 token，而不是直接跳到答案**。

准确率提升：**15-25%**（在多步推理任务上）。

### 两种模式

| 模式 | 做法 | 适用 |
|------|------|------|
| **Zero-shot CoT** | 末尾加一句「请一步一步展示推理过程」 | 通用场景 |
| **Few-shot CoT** | 提供完整的「问题→推理步骤→答案」示例 | 格式敏感场景 |

### 关键约束

CoT 提示词必须指定最后一行格式（如「最后一行以'答案：'开头」），或直接用结构化输出。否则模型写的步骤格式随意，导致后处理代码崩。

---

## 三、Self-Consistency：多路径投票

### 核心原理

同一个问题，LLM 不同次运行可能给出不同答案（Temperature > 0 时尤其明显）。

```
问题 → [CoT路径1 → 答案A]
     → [CoT路径2 → 答案A]  → 投票 → 答案A（2票赢）
     → [CoT路径3 → 答案B]
```

**论文数据**（Wei et al., 2022）：数学推理 +10-17%，常识推理 +13%。

### 使用条件

| 场景 | 是否值得用 SC |
|------|-------------|
| 精确数学/逻辑推理 | ✅ 值得 |
| 代码生成（多版本取最多数） | ✅ 值得 |
| 简单问答/信息检索 | ❌ 不值得 |
| 开放式创意写作 | ❌ 无意义 |
| 实时响应（<500ms） | ❌ 太慢 |

### 参数建议

- N 至少设为奇数（3、5），避免平票
- Temperature 设 0.5~0.8 保证路径多样性

---

## 四、三者组合：生产级方案

单独用这三个技术都很基础，组合起来才是生产级的用法。

### 效果与成本

| 策略 | 推理准确率 | 相对成本 | 延迟 | 适用场景 |
|------|-----------|---------|------|---------|
| Zero-shot | 基准 | 1x | 低 | 简单任务 |
| Few-shot | +10-15% | 1.2x | 低 | 格式敏感任务 |
| CoT | +15-25% | 1.3x | 中 | 多步推理 |
| Few-shot + CoT | +25-35% | 1.5x | 中 | 复杂推理 |
| Self-Consistency (N=5) | +35-50% | 5x | 高 | 高精度任务 |

### 动态路由策略

不是所有问题都需要 CoT。用路由逻辑动态决定：

- **70% 简单问题**：直接 Zero-shot（省成本 80%）
- **30% 复杂问题**：Few-shot CoT + Self-Consistency（保准确率）

**总体效果**：相比全量上 SC，成本降低约 75%，平均延迟降低约 60%。

## 六个常见坑

1. **Few-shot 示例质量差** → 比不给更糟。每次改 Prompt 先跑测试用例
2. **CoT 未指定输出格式** → 后处理代码崩。明确最后一行格式
3. **SC 的 N 值设太小** → N=2 平票无法决出。至少奇数 3/5
4. **工具调用 Agent 里用 CoT** → 工具参数提取变差。把推理放在独立字段
5. **Prompt 改好了但不知道为什么** → 下次模型升级又崩。Prompt 当代码管理
6. **测试集太小** → 10 条调出来的在生产 10 万条上崩。至少 100+ 条覆盖边界

## 与 Agent 的关系

这三板斧是 Agent 推理能力的基础支撑：

- **Few-shot** → 校准 Agent 的工具调用格式
- **CoT** → 让 Agent 在「思考→行动→观察」循环中多步推理
- **Self-Consistency** → Agent 执行关键决策时多路径验证

在 [[../topics/claude-code-prompt-engineering|Claude Code 提示词工程]] 中，结构化 Prompt 模板本质上就是这三板斧的具体应用。

---

> 实用建议：先上 Few-shot + CoT，只对准确率要求极高的核心路径加 Self-Consistency。Prompt 的核心是「把 AI 当同事沟通，而非给机器下命令」。
