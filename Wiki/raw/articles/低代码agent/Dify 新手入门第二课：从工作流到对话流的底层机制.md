## 一、Dify 的定位与核心概念

Dify 的设计理念是 **“把 AI 能力转化为可控、可编排、可复用的流程”** 。平台核心概念包括：

- **智能体（Agentic App）** ：一个可执行的流程，由节点组成，负责处理输入并产出输出。
- **Workflow / Chatflow** ：两类核心应用类型。Workflow 适合自动化任务或脚本式逻辑，Chatflow 适合多轮交互、保持会话上下文。
- **节点（Node）** ：工作流中的基本单元，每个节点负责一小步操作，例如调用模型、检索知识、条件分支或输出。
- **可视化编辑** ：通过拖拽节点、连接输入输出线，用户无需写大量代码即可搭建完整流程。

> 与传统代码不同，Dify 通过 DAG（有向无环图）表示节点依赖，确保执行顺序和可追踪性。

## 二、核心架构概览

Dify 的架构可以划分为四层：

1. **前端交互层**
- 用户输入界面、对话窗口、表单和模块拖拽页面。
	- 支持 Chatflow 对话历史显示、输入输出管理。
3. **智能体执行层（Engine）**
- **模型节点（LLM）** ：调用语言模型生成文本或结构化输出。
	- **知识库节点（RAG）** ：向量检索 + 文本增强生成。
	- **工具节点** ：调用外部 API 或执行脚本。
	- **条件分支节点** ：IF/CASE 判断，控制流程走向。
- 核心是 DAG 执行引擎。
	- 节点类型包括：
6. **模型与数据层**
- 多模型管理、参数配置（温度、Top-K 等）。
	- 知识库支持向量搜索、混合检索模式。
	- 日志记录与监控：节点执行状态、错误追踪、历史回溯。
8. **发布与运维层**
- Web App / API / MCP Server 等多种发布方式。
	- 版本控制、权限管理、错误定位、回滚功能。

## 三、Workflow 与 Chatflow 的核心区别

| 特性 | Workflow | Chatflow |
| --- | --- | --- |
| 触发机制 | 用户输入或触发器（Webhook/定时） | 用户消息触发 |
| 状态管理 | 一次执行，无状态 | 多轮对话，可保留上下文 |
| 条件控制 | IF/Branch | IF/Branch + 上下文记忆 |
| 适用场景 | 自动化任务、数据处理 | 对话助手、客户交互 |

> Chatflow 在 Workflow 基础上增加了会话记忆、上下文变量和多轮对话支持。

## 四、核心节点与属性拆解

下面是 Dify 核心节点的技术细节：

1. **用户输入节点**
- **属性** ：ID、标签、输入类型（文本/选择/文件）、上下文引用
	- **作用** ：捕获用户输入，触发流程
3. **模型节点（LLM）**
- **属性** ：模型类型、提示模板、输出类型（文本/JSON）、错误策略（重试/跳过）
	- **作用** ：调用 AI 模型生成输出，可接入本地或云端模型
5. **知识库检索节点**
- **属性** ：知识库选择、Top-K、向量维度、查询模板
	- **作用** ：RAG 查询，增强 AI 响应准确性
7. **条件分支节点**
- **属性** ：条件表达式、分支路径
	- **作用** ：根据逻辑判断选择执行路线
9. **输出节点**
- **属性** ：输出目标（界面/API/文件）、格式化选项
	- **作用** ：返回最终结果或触发下一步动作
11. **变量体系**
- **输入变量** ：用户或触发器提供
	- **节点输出变量** ：用于后续节点
	- **会话变量** ：跨轮次保存上下文

> 所有节点均可在 DAG 中复用，变量在节点间传递，形成完整执行链。

---

## 五、工作流执行逻辑

1. **用户输入 → 输入变量提取**
2. **节点序列执行** ：每个节点处理输入，生成输出变量
3. **条件分支处理** ：根据 IF 节点判断下一节点
4. **知识库查询（可选）** ：RAG 检索
5. **AI 响应生成 → 输出节点展示**
6. **Chatflow 多轮对话** ：会话变量用于上下文记忆
7. **错误处理 / fallback** ：节点异常可触发重试或备用路径

## 六、DSL 与应用迁移

- Dify 支持将 App 导出为 DSL（YAML/JSON），包含节点定义、变量、流程拓扑。
- 用途：
- 版本控制
	- 应用迁移
	- 自动化构建/复用
	- CI/CD 集成
	- 场景测试与自动生成测试数据

---

## 七、发布与扩展能力

- **Web App** ：浏览器可直接访问的 Chatflow
- **API** ：RESTful 接口，方便集成到企业系统
- **MCP Server** ：标准协议发布能力
- **插件市场** ：可安装模型、工具或策略扩展

> 发布后的 Chatflow 可提供持久历史、多线程会话、预聊表单、语音输入等功能。

## 八、总结与实践价值

Dify 并非简单的低代码平台，它把 **AI 模型接入、知识库查询、条件分支和外部工具调用** 融合到 **可视化 DAG 流程** 中，使智能体开发更可控、可扩展和可复用。理解它的节点、变量体系、工作流与对话流机制，是构建企业级智能体系统的核心前提。

## 九、核心节点清单与属性表（附表）

| 节点类型 | 属性 | 输入 | 输出 | 错误处理 | 描述 / 说明 |
| --- | --- | --- | --- | --- | --- |
| **用户输入节点** | ID、标签、输入类型（文本/选择/文件）、上下文引用 | 用户输入 | 输入变量 | 无 / 流程终止 | 捕获用户消息或触发器输入，触发流程执行 |
| **模型节点（LLM）** | 模型类型、提示模板、输出类型（文本/JSON）、温度、Top-K | 上游节点变量 | AI 输出变量 | 重试 / 跳过 / Fallback | 调用 LLM 或自定义模型生成文本或结构化结果 |
| **知识库检索节点** | 知识库选择、Top-K、向量维度、查询模板 | 上游节点变量 | 检索结果变量 | 跳过 / 空结果处理 | 结合 RAG 技术进行向量检索增强 AI 响应 |
| **HTTP / Tool 节点** | API URL、Method、Headers、Body、超时 | 上游节点变量 | API 调用返回 | 重试 / 抛错 / Fallback | 调用外部服务或执行工具操作，返回结果供下游使用 |
| **条件分支节点（IF / CASE）** | 条件表达式、分支路径 | 上游节点变量 | 路径选择（无输出变量） | 路径默认 / 抛错 | 根据逻辑判断选择下一节点执行路线 |
| **输出节点** | 输出目标（界面/API/文件）、格式化选项、变量引用 | 上游节点变量 | 最终输出 | 终止流程 / 抛错 | 将流程结果返回给前端、API 或文件系统 |
| **变量节点 / 运算节点** | 变量名称、类型、表达式 / 运算规则 | 上游节点变量 | 输出变量 | 抛错 / 默认值 | 处理数据计算、条件判断、数组或对象操作 |
| **循环节点（LOOP / FOREACH）** | 循环条件、迭代变量 | 上游节点变量 | 循环输出 | 跳过 / 异常终止 | 对集合或数组执行重复逻辑操作 |
| **会话管理节点** | 变量作用域、保存策略 | 上游节点变量 | 会话变量 | 持久化异常处理 | Chatflow 专用，保存多轮对话上下文 |
| **错误处理节点 / Fallback** | 异常类型、处理策略 | 上游节点变量 | 修正结果 / 默认值 | 重试 / 跳转 | 捕获上游异常或空结果，保证流程可继续执行 |

> 💡 注意：在实际流程中，每个节点可引用前节点输出的变量，形成完整的 DAG 执行链。Chatflow 中的会话变量允许跨轮次引用，Workflow 则通常一次性执行。
