# 第一章：MVP 架构设计

> 📖 对应学习计划 Day 1-2。设计 MVP 的七层架构，打通核心链路。

---

## 1.1 七层架构

```
┌──────────────────────────────────────┐
│  7. 运维层：LLMOps + 安全审计        │ ← Token 监控 · 报错率 · 安全扫描
├──────────────────────────────────────┤
│  6. 应用层：Dify + Coze              │ ← RAG 问答入口 · Agent 对外分发
├──────────────────────────────────────┤
│  5. 智能体层：Agent + MCP + FC       │ ← 核心调度 · 工具调用 · 通信协议
├──────────────────────────────────────┤
│  4. 知识层：Chroma + Agentic RAG     │ ← 矢量存储 · 智能检索 · 知识问答
├──────────────────────────────────────┤
│  3. 编码层：Trae/Cursor + Vibe Coding│ ← 本地 IDE · 自然语言编程
├──────────────────────────────────────┤
│  2. 约束层：Rule + Skills            │ ← 全局规则 · 可复用技能包
├──────────────────────────────────────┤
│  1. 底座层：Ollama + 云端 API        │ ← 本地模型 · 云端切换 · 自动降级
└──────────────────────────────────────┘
```

### 每层的职责与接口

| 层级 | 核心职责 | 对外接口 | 关键组件 |
|------|---------|---------|---------|
| **底座层** | 模型供应与切换 | 统一 API（兼容 OpenAI 格式） | Ollama + Claude/DeepSeek API + 自动降级 |
| **约束层** | 行为规范注入 | CLAUDE.md /.cursorrules 文件 | 通用 Rule + 项目 Rule + Skills |
| **编码层** | 代码生成与编辑 | IDE 插件 / CLI | Trae / Cursor / Claude Code |
| **知识层** | 项目知识检索 | 向量搜索 API | Chroma + Agentic RAG |
| **智能体层** | 任务规划与执行 | Agent API（工具调度） | Agent 调度器 + MCP + Function Calling |
| **应用层** | 用户交互与分发 | Web UI / REST API | Dify + Coze |
| **运维层** | 监控与安全 | Dashboard / Alert | LLMOps 面板 + 安全扫描器 |

---

## 1.2 核心链路

```
用户需求
  ↓
[底座层] Ollama 本地模型（简单任务）/ Claude API（复杂任务）
  ↓
[约束层] Rule 自动注入（项目规范 + 个人偏好）
  ↓
[编码层] AI IDE 生成代码，Vibe Coding 迭代
  ↓
[知识层] Agentic RAG 检索项目知识库，补充上下文
  ↓
[智能体层] Agent 调度工具（读文件 → 写代码 → 跑测试 → Git）
  ↓
[应用层] Dify 后台面板 / Coze API 对外分发
  ↓
[运维层] LLMOps 监控 Token/报错/安全
```

### 核心链路的设计原则

1. **每层独立可替换**：底座层可以切换 Ollama ↔ 云端 API，不影响上层
2. **层层注入上下文**：下层为上层提供更丰富的上下文，不丢失信息
3. **失败向上传播**：底层错误不静默处理，逐层上报
4. **监控贯穿全链路**：运维层监控每一层的健康状态

## 1.3 MVP 范围定义

### MVP 必须包含（核心链路）

- [x] 本地 Ollama + 云端 API 双通道自动切换
- [x] 全局 Rule 文件（CLAUDE.md）自动加载
- [x] 3+ 可复用 Skills（接口生成 / SQL 编写 / 代码审查）
- [x] Chroma 向量库 + 项目知识库检索
- [x] Agent 核心调度器（规划 → 执行 → 验证）
- [x] 基础 LLMOps（Token 消耗 + 报错率）

### MVP 留给后续迭代（预留接口）

- [ ] Dify 私有化后台面板
- [ ] Coze 多渠道分发
- [ ] 多 Agent 协同
- [ ] 自动化 CI/CD 集成
- [ ] 完整安全审计管线

### MVP 的验收标准

| 标准 | 验证方法 |
|------|---------|
| **核心链路可用** | 输入一个真实开发任务，端到端走完 7 层 |
| **自动降级可用** | 断开网络 → Ollama 自动接管 → 核心功能正常 |
| **Token 监控可见** | 完成一个任务后，Token 面板显示消耗数据 |
| **安全扫描执行** | 对 AI 生成的代码运行安全扫描，能发现硬编码密钥 |
| **资产可复用** | 将 MVP 配置复制到新项目，核心链路在 30 分钟内跑通 |

## 1.4 MVP 技术选型决策

| 层级 | 技术选项 | 推荐 | 理由 |
|------|---------|------|------|
| 底座层 | Ollama / vLLM / LM Studio | Ollama | 最简单、社区最活跃 |
| 向量库 | Chroma / Milvus / Pinecone | Chroma | 零配置、适合 MVP 阶段 |
| 知识层 | 基础 RAG / Agentic RAG | 基础 RAG（MVP） | Agentic RAG 留给后续迭代 |
| Agent 框架 | LangChain / 手写 | 手写核心 | MVP 阶段避免框架依赖 |
| 应用层 | Dify / 自研 Web | Dify | 快速搭建、无需前端 |

> 💡 **MVP 铁律**：选最简单的方案，跑通核心链路。不要在 MVP 阶段追求完美——后续迭代中，你会根据真实使用数据知道哪些模块需要升级。
