## 4.1 资产库结构

```
~/.ai-assets/
├── prompts/              # Prompt 模板库
│   ├── code-gen.md       # 代码生成 Prompt
│   ├── bug-fix.md        # Bug 修复 Prompt
│   ├── code-review.md    # 代码审查 Prompt
│   ├── sql-gen.md        # SQL 生成 Prompt
│   └── api-design.md     # API 设计 Prompt
├── rules/                # Rule 规则文件
│   ├── global.md         # 全局通用 Rule
│   ├── frontend.md       # 前端项目 Rule
│   └── backend.md        # 后端项目 Rule
├── skills/               # 自定义 Skills
│   ├── api-generator/
│   ├── sql-writer/
│   └── test-generator/
├── agents/               # Agent 配置
│   ├── dev-agent.json    # 开发 Agent
│   └── review-agent.json # 审查 Agent
├── mcp/                   # MCP 配置
│   └── mcp.json
└── monitoring/            # 监控配置
    └── llmops-config.json
```

### 资产库初始化脚本

```bash
#!/bin/bash
# init-ai-assets.sh — 一键初始化个人 AI 资产库

ASSETS_DIR="$HOME/.ai-assets"

echo "🚀 初始化 AI 资产库：$ASSETS_DIR"

# 创建目录结构
mkdir -p "$ASSETS_DIR"/{prompts,rules,skills,agents,mcp,monitoring}

# 复制通用 Rule 模板
cat > "$ASSETS_DIR/rules/global.md" << 'EOF'
# 全局 AI 调用强制规则

## 1. 身份定位
你是资深软件开发工程师。输出内容贴合工业级开发标准。

## 2. 代码优先原则
- 直接给代码，少解释
- 代码必须可直接运行
- 不确定的 API/参数标注 TODO: verify

## 3. 最少修改原则
- 只改实现当前目标必需的代码
- 不改相邻代码和注释
- 匹配现有代码风格

## 4. 不确定性原则
- 不确定就问，不要猜
- 有 2+ 可行方案时列出 trade-off

## 5. 简单优先原则
- 用最少代码解决问题
- 不为「可能的未来需求」写抽象层
EOF

# 复制 LLMOps 配置模板
cat > "$ASSETS_DIR/monitoring/llmops-config.json" << 'EOF'
{
  "daily_budget": 10.0,
  "alert_threshold": 0.8,
  "session_budget": 30000,
  "models": {
    "default": "claude-sonnet-4",
    "fallback": "deepseek-coder:6.7b"
  },
  "security_scan": {
    "enabled": true,
    "scan_on_commit": true,
    "file_patterns": ["*.py", "*.js", "*.ts", "*.tsx", "*.jsx"]
  }
}
EOF

echo "✅ 资产库初始化完成！"
echo "📂 路径：$ASSETS_DIR"
echo ""
echo "下一步："
echo "  1. 将你的 Prompt 模板复制到 prompts/"
echo "  2. 将自定义 Skills 复制到 skills/"
echo "  3. 设置符号链接：ln -s ~/.ai-assets/rules/global.md ./CLAUDE.md"
```

## 4.2 资产复用检查清单

完成第 8 周后，应确保以下资产可跨项目复用：

- [ ] **Prompt 模板 8 套**：功能实现 / Bug 修复 / 代码审查 / 代码重构 / SQL 生成 / 测试生成 / API 设计 / 技术方案
- [ ] **Rule 文件 3 套**：全局通用 / 前端项目 / 后端项目
- [ ] **Skills 6 个**：api-generator / sql-writer / code-refactor / test-generator / tech-review / security-audit
- [ ] **Agent 配置**：开发 Agent（含工具列表+系统提示词）、审查 Agent
- [ ] **MCP 组合**：按项目类型预设的 MCP 列表
- [ ] **LLMOps 脚本**：Token 监控 / 质量追踪 / 安全扫描

### 资产验证方法

| 资产类型 | 验证方法 |
|---------|---------|
| Prompt 模板 | 用同一个 Prompt 在新项目中跑 3 个用例，成功率 > 80% |
| Rule 文件 | 部署到新项目，AI 行为符合约束（如只改必要代码） |
| Skills | 在新项目中触发 Skill（如「生成 API」），产出格式一致 |
| Agent 配置 | 部署 Agent 到新项目，核心工具调用正常 |
| MCP 配置 | `claude mcp list` 显示正确的 MCP 列表 |
| LLMOps 脚本 | 运行脚本，面板显示正确数据 |

## 4.5 长期维护策略

### 资产库的版本管理

```bash
# 初始化 Git 仓库
cd ~/.ai-assets
git init
git add -A
git commit -m "init: AI assets library"

# 每次修改后提交
git add -A
git commit -m "update: add sql-writer skill"
```

### 定期审计（每月一次）

- [ ] 清理不再使用的 Prompt/Skill（减少 AI 的选择困难）
- [ ] 更新 Rule 文件（适配新的 AI 模型版本）
- [ ] 检查 MCP 配置（新版本是否有 breaking change）
- [ ] 运行安全扫描（检查资产库本身是否包含敏感信息）

### 知识持续更新

AI Coding 领域每月都有新工具、新方法。保持更新的方式：

1. **关注知识库更新**：`Wiki/wiki/` 会持续收录新资料
2. **每周浏览一次 index.md**：快速了解新增内容
3. **参加社区讨论**：Claude Code Discord、Cursor 论坛
4. **实践驱动更新**：每遇到一个新的翻车场景，补一条 Rule 或 Skill
